\subsection{Offline companion verification}

The standalone verification surface is \IdentityText{\CompanionFilenameRaw}, size

public URL; the ZIP must be delivered with the PDF. From a directory containing the ZIP:

\begin{verbatim}
sha256sum fl-bsa-v5.0.1-companion-evidence.zip
mkdir fl-bsa-v5.0.1-companion-evidence
python3 -m zipfile -e fl-bsa-v5.0.1-companion-evidence.zip \
  fl-bsa-v5.0.1-companion-evidence

  fl-bsa-v5.0.1-companion-evidence.zip

\subsection{Whitepaper build}

At whitepaper commit \IdentityText{\WhitepaperCommitRaw}, the reviewed build sequence is:

\begin{verbatim}
python3 -m unittest discover -s tests
make pdf
make arxiv
\end{verbatim}

The PDF target regenerates strict evidence macros, old compatibility figures, the six
characterization visuals, the paper-owned summary, the deterministic companion, and the untracked
self-identity include before compiling. A release candidate is rebuilt only from a clean source
checkout so its paper commit and companion manifest agree. The PDF is built twice in verification
to confirm deterministic bytes; fonts, bookmarks, language metadata, tags, and alternative text
are separately inspected because byte determinism does not imply accessibility.
