\subsection{Offline companion verification}

The standalone verification surface is \IdentityText{\CompanionFilenameRaw}, size
\CompanionSizeRaw{} bytes, with SHA-256 \IdentityText{\CompanionShaRaw}. This candidate has no
public URL; the ZIP must be delivered with the PDF. From a directory containing the ZIP:

\begin{verbatim}
sha256sum fl-bsa-v5.0.1-companion-evidence.zip
mkdir fl-bsa-v5.0.1-companion-evidence
python3 -m zipfile -e fl-bsa-v5.0.1-companion-evidence.zip \
  fl-bsa-v5.0.1-companion-evidence
python3 fl-bsa-v5.0.1-companion-evidence/verify_companion_bundle.py \
  --expected-utility-sha256 \
  2b05a4a2b7ce2d798b9156ed5f837efe890ee87e4f5e914497724802636e4595 \
  fl-bsa-v5.0.1-companion-evidence.zip
\end{verbatim}

The first command must match the digest printed on the cover. Only then should the bundled
standard-library verifier be extracted and run against the delivered ZIP. It rejects unsafe,
duplicate, oversized, or unexpected archive members; checks every file size and SHA-256 in
\path{MANIFEST.json}; reconstructs and hashes the original producer ZIP; verifies the exact
product, workflow, and customer/publication identities; recomputes the displayed Wilson, AIR, SRG,
two-proportion, and Holm arithmetic; and traverses the complete certificate graph. For robustness
it checks the exact seed set, per-seed statuses, and aggregates for all 40 Gold runs. The utility
SHA-256 argument must be copied from the trusted PDF; the verifier consumes that supplied value and
does not read the PDF. It requires
\path{evidence/v5.0.1/utility/utility_summary.json} to match, then validates the ten-row structure,
recomputes aggregates and skill retention, and cross-checks the paper-owned headline
characterization. A coherent rewrite of utility rows, bands, derived summary, bundled digest
constant, and ZIP manifest therefore still fails when the original PDF value is supplied. The
verifier does not independently authenticate a modified ZIP or regenerate generator outputs or
model predictions; the preceding whole-ZIP digest comparison is the trust anchor, and full utility
reproduction still requires the exact product checkout and recorded dependencies.

No instruction depends on an unbundled repository-relative evidence file. The current regulatory
overlay is at
\path{evidence/v5.0.1/publication/regulatory_mapping_2026-08-05.csv}; the complete derived
characterization is at \path{evidence/v5.0.1/publication/characterization_summary.json}.

\subsection{Utility reproduction}

The companion verifier hashes the supplied fixture and requires the paper-owned utility summary
bytes to match the caller-supplied PDF digest. It validates relations and aggregates inside that
bound summary; it does not read the PDF or regenerate generator outputs or model predictions. Full
reproduction requires an exact checkout of product tag v5.0.1 and its Python dependencies:

\begin{verbatim}
python3 scripts/evaluate_fixture_utility.py \
  --product-root /path/to/exact-v5.0.1-checkout \
  --fixture evidence/v5.0.1/utility/balanced_fixture.csv.gz \
  --output /tmp/utility_summary.json
sha256sum /tmp/utility_summary.json
\end{verbatim}

The product checkout is rejected unless \texttt{git describe --exact-match} returns v5.0.1 and
HEAD equals:
\begin{center}
  \IdentityText{\ProductCommitRaw}
\end{center}
The paper-owned summary drives headline macros and figures but is not producer-signed. Its exact
bytes are therefore anchored separately from the companion manifest. Under the recorded Python,
NumPy, pandas, and scikit-learn versions, a matching result has SHA-256:
\begin{center}
  \IdentityText{\UtilitySummaryShaRaw}
\end{center}
A coherent rewrite of utility rows, aggregates, and the derived characterization fails the
unmodified verifier when the PDF-disclosed digest is supplied, even if the companion manifest is
repaired.

\subsection{Whitepaper build}

At whitepaper commit \IdentityText{\WhitepaperCommitRaw}, the reviewed build sequence is:

\begin{verbatim}
make publication-candidate
\end{verbatim}

The publication-candidate target runs the full test suite; regenerates strict evidence macros, old
compatibility figures, the six characterization visuals, the paper-owned summary, and the
deterministic companion; selects the reviewed demo/evaluation profile; clears prior LaTeX auxiliary
state; and emits the PDF, arXiv source, compatibility export, and hash-bound publication manifest.
It refuses a dirty source checkout so the paper commit and companion manifest agree. The complete
target is run twice in verification to confirm deterministic bytes; fonts, bookmarks, language
metadata, tags, and alternative text are separately inspected because byte determinism does not
imply accessibility.

\subsection{Source hierarchy}

The exact producer intake remains unchanged except for the deterministic whitepaper-consumer stamp.
Paper-owned corrections live under \path{evidence/v5.0.1/publication/}. This separation permits a
reviewer to distinguish original evidence, a corrected interpretation, and a derived study. The
companion manifest hashes all three layers and states that the candidate is not published.
