\subsection{Offline companion verification}

The standalone verification surface is \IdentityText{\CompanionFilenameRaw}, size
\CompanionSizeRaw{} bytes, with SHA-256 \IdentityText{\CompanionShaRaw}. This candidate has no
public URL; the ZIP must be delivered with the PDF. From a directory containing the ZIP:

\begin{verbatim}
sha256sum fl-bsa-v5.0.1-companion-evidence.zip
mkdir fl-bsa-v5.0.1-companion-evidence
python3 -m zipfile -e fl-bsa-v5.0.1-companion-evidence.zip \
  fl-bsa-v5.0.1-companion-evidence
python3 fl-bsa-v5.0.1-companion-evidence/verify_companion_bundle.py \
  fl-bsa-v5.0.1-companion-evidence.zip
\end{verbatim}

The first command must match the digest printed on the cover. Only then should the bundled
standard-library verifier be extracted and run against the delivered ZIP. It rejects unsafe,

product, workflow, and customer/publication identities; recomputes the displayed Wilson, AIR, SRG,
two-proportion, and Holm arithmetic; and traverses the complete certificate graph. For robustness
it checks the exact seed set, per-seed statuses, and aggregates for all 40 Gold runs. For utility it

printed below, then validates the ten-row structure and recomputes aggregates and skill retention
from those digest-bound rows. It cross-checks the paper-owned headline characterization against
those layers. Repairing the ZIP manifest and derived summary cannot substitute for the PDF-disclosed
utility digest. The verifier does not regenerate generator outputs or model predictions; full
utility reproduction still requires the exact product checkout and recorded dependencies.

No instruction depends on an unbundled repository-relative evidence file. The current regulatory

\subsection{Utility reproduction}

The companion verifier hashes the supplied fixture and requires the paper-owned utility summary
bytes to match the PDF-disclosed digest. It validates relations and aggregates inside that bound
summary; it does not regenerate generator outputs or model predictions. Full reproduction requires
an exact checkout of product tag v5.0.1 and its Python dependencies:

\begin{verbatim}
python3 scripts/evaluate_fixture_utility.py \
  --product-root /path/to/exact-v5.0.1-checkout \
  --fixture evidence/v5.0.1/utility/balanced_fixture.csv.gz \
  --output /tmp/utility_summary.json
sha256sum /tmp/utility_summary.json
\end{verbatim}

\subsection{Whitepaper build}

At whitepaper commit \IdentityText{\WhitepaperCommitRaw}, the reviewed build sequence is:

\begin{verbatim}
make publication-candidate
\end{verbatim}

The publication-candidate target runs the full test suite; regenerates strict evidence macros, old
compatibility figures, the six characterization visuals, the paper-owned summary, and the
deterministic companion; selects the reviewed demo/evaluation profile; clears prior LaTeX auxiliary
state; and emits the PDF, arXiv source, compatibility export, and hash-bound publication manifest.
It refuses a dirty source checkout so the paper commit and companion manifest agree. The complete
target is run twice in verification to confirm deterministic bytes; fonts, bookmarks, language
metadata, tags, and alternative text are separately inspected because byte determinism does not
imply accessibility.
