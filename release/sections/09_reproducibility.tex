
\section{Reproducibility}
Every table in this paper is tied to a run identifier and a manifest. The manifest records the dataset hash, code commit, container image digests, random number generator seed, hardware description, and start/end timestamps, as summarised in Appendix~E.

\subsection{How to verify this bundle}
\begin{enumerate}[leftmargin=*]
\item Check \path{intake/manifest.json} for the FL-BSA code commit, run identifier, dataset hash, image digests, seeds, and \path{customer_evidence_eligible=false} posture.
\item Check \path{intake/fairness_slices.json} and \path{intake/metrics_uncertainty.json}; the historical, amplification, and intrinsic AIR values in \Cref{tab:gender_air_slices,fig:gender_air_slices} are rendered from those files.
\item Regenerate derived TeX and figures with \texttt{make release-assets}; this rewrites \path{release/includes/metrics_macros.tex}, \path{release/includes/provenance_macros.tex}, \path{release/includes/table_regulatory_matrix.tex}, and the release-scoped PDF figures from the exact intake.
\item Rebuild with \texttt{make release-pdf}. Confirm that the rendered PDF carries the exact product, evidence-run, whitepaper-source, and intake-snapshot identities plus the demo/evaluation marker.
\item Inspect \path{intake/pack_intent.json} and \path{intake/certificates/*.json} before relying on signatures; this whitepaper bundle is intentionally unsigned review evidence, while GOLD evidence bundles carry certificate signatures when that mode is enabled.
\end{enumerate}

In addition, the whitepaper intake bundle includes unsigned certificate hashes and predecessor links (JSON) that provide integrity linkage when a reviewer independently recomputes them; \path{intake/pack_intent.json} records \path{certificate_signing_expected=false}. Without an independently trusted signature or external digest, those links do not authenticate authorship and are not standalone tamper proof. When certificate signing is enabled for GOLD evidence bundles, certificates are ECDSA P-256 signed and record signature material in fields such as \path{certificate_signature}, \path{signature_algorithm}, and \path{public_key_fingerprint}. For cryptographically verifiable certificate signatures, reviewers should use the GOLD evidence bundles and certificate-chain outputs rather than this whitepaper intake bundle.
